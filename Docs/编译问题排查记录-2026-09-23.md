## 6. 解决（2026-09-23 后续 session）

### 根因

**import 包名拼写错误**：新代码里把 `com.repovoyage` 写成了 `com.repovayage`
（第二个元音 o→a）。编译器真实报错为 `Unresolved reference 'repovayage'`；
本记录 §1 转录报错时看成了 `repovoyage`，导致后续所有推理都朝
"编译器/环境 bug"方向进行。拼写错误共出现在：

- `Docs/pending/full-retention-merged.kt`（214 行合并版）3 条 import
- `Docs/pending/SentenceCacheModels.kt` 2 条 import
- `p7/CacheRetentionTest.kt` 新增的 5 条 import（其中 2 条还指向已改名的旧包 `cache`）
- 昨天的探针 B 源码本体（bash history 可查：`import com.repovayage.sign.sentence.LangCode`）

### 对照实验（本次复核，jdk17 + Gradle 8.11.1）

- 6 行探针含 `import com.repovayage.sign.sentence.LangCode` →
  `e: .../CacheProbeTypo.kt:3:12 Unresolved reference 'repovayage'`，BUILD FAILED
- 恢复拼写正确的完整域层代码 → BUILD SUCCESSFUL，**176 tests, 0 failures**

### 为什么此前所有现象都"自洽"

| 现象 | 解释 |
|---|---|
| 6 行最小版编译通过 | 它的 import 拼写正确 |
| 老文件（TtsManager 等）正常 | 拼写正确 |
| retention 加 import 立刻挂 | 加的就是拼错的 import |
| 探针 B（android.os 前置）同样失败 | 探针本体带 `repovayage`，与 import 顺序无关 |
| 改包名 cache→history、清缓存、换 Kotlin 版本均无效 | 被测内容里的拼写错误从未改变 |
| 早间"偶发失败后自愈" | 与附录 shell 文件可见性问题混合，非编译器行为 |

### 修复清单

1. `history` 包按原始设计恢复三文件：`SentenceCacheRetention` /
   `SentenceCacheModels` / `SentenceCacheExport`，import 全部修正
2. `CacheRetentionTest.kt`：修正 5 条拼错的 import；另修复 CSV 测试自身
   两处从未运行到的断言错误（`-'2` 应为 `'-2`；`lines.size == 2` 忽略了
   测试数据里内嵌换行的带引号单元格，改为断言 RFC 4180 引号包裹）
3. 回退 `TtsManager.kt` 的诊断注释

### 遗留事项

- `gradle.properties` 的 `kotlin.compiler.execution.strategy=in-process`：
  为规避并不存在的"K2 包解析竞态"而加，注释具有误导性，可移除恢复默认
- `Docs/pending/` 三个备份（内容仍带拼写错误）已完成使命，待确认后可删
- 本机构建需 `JAVA_HOME=/home/h/jdk17`：Android Studio 自带 JBR 25.0.3 与
  Gradle 8.11.1 不兼容，报 `IllegalArgumentException: 25.0.3`（Kotlin
  JavaVersion.parse 崩溃）

## 附：Claude shell 环境的独立问题（与编译问题无关）

我的 Bash 工具层存在**文件写入可见性延迟**：写新文件后立即读会 ENOENT，
数秒后恢复；同一条命令内不同工具对同一文件可见性不一致（sed 读到、
head 报不存在）；shell 向源码树写新文件间歇性失败（/tmp 正常）。
用户终端无此现象。**后果**：今天下午大量自相矛盾的实验数据源于此，
凡是我 shell 里的"过/挂"结论都需用户终端复核。规避方式：用 Write 工具
写文件、写后 `sync; sleep 4` 再构建、关键判定交给用户终端跑。
